3. WHAT THE PRESS COST -- THREE REFUSALS, ALL BEFORE SENDING (the presses that did send: one)
====================================================================================================
  (i)   The gate refused: the entry sources manifest named build_entry.sh's OLD sha because the
        registration edit preceded the build -- and the rebuild, then, did not rewrite the manifest.
        The entry image is a function of src/entry/ only; the reproducible rebuild with the arm
        record's switches produced a NEW bin (source -> product, not a lookup problem).
  (ii)  The gate refused: an entry binary of a NEW size was embedded in a payload built for the OLD
        one (the containment test in preflight, by content).  The payload must be rebuilt with
        STAGE90_EXTRA_CFLAGS = the arm record's switches + -DSTAGE90_XNU_ENTRY=1, and
        XNU_TREE=<hd2-darwin13>.  A payload rebuilt WITHOUT the entry switch was refused by the
        runner at zero cost ("STAGE90_XNU_ENTRY off").
  (iii) The gate refused: the live pack was a set nobody recorded -- see 4(a)-(c).
4. DEFECTS FOUND BY THESE REFUSALS (each a named class; fixes are in this hour's commit)
====================================================================================================
  (a) A SET NAMED BY ONE MEMBER CAN HOLD ANOTHER BUILD.  park_1037.sh named the set by the entry
      bin's sha8, and two parks of the same bin (trap.c-only, then trap.c + registration) wrote the
      same set name; the second park's cp of the payload members hit ENOENT (out/ still held the old
      names) and `set -e` did not stop the record write, so out/ became trap.c(new)+payload(old) -- a
      MIXED set.  FIX: the set is named by the sha of EVERY member (a content name), so a second park
      of a changed pack cannot reuse the name.
  (b) PRESS RESOLVED THE ARM BY RECOMPUTING IT.  press_1037.sh derived EXPECT_ARM as armed-d13-<bin
      sha8> instead of reading the recorded set -- one value, two definitions, and with (a)'s fix the
      two disagree by construction.  FIX: EXPECT_ARM := tools/resolve_arm_set.sh out/stage90 | cut -f1.
  (c) A PARK THAT FAILS MIDWAY LEAVES A RECORD.  The cp loop's failure was invisible to the record
      writer.  FIX in the fix's shape, not the writer's: a pack copy that fails is now a pack that is
      not named (the content name changes), so the gate's "NO recorded set" refusal catches it.
  (d) THE PRESS LAUNCHER COULD NOT FORWARD THE RUNNER'S FLAGS (so --self-test, the only no-send
      exercise, could not be run through it).  FIX: "$@" is forwarded at the runner call.
  (e) AN EMPTY-BUT-SET ARM KEY MADE THE ENTRY RECORD UNREADABLE (TRAP_FRAME= , WATCH_LE=: the
      environment carried them empty; the value case left _v empty).  FIX: both normalize an empty
      value to 0 in build_entry.sh.
  (f) THE MUTATION SWEEP COULD NOT RUN FOR THIS BUILD AND SAID SO ("the arm it describes is not
      known") because the record carried the two empty keys above; from this build on it can.
