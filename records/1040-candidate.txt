WHAT IS AND IS NOT 1032'S FAULT
  1032 widened the guard from `count == 0` to `count < 1` so a negative count stops running away.
  That is correct and stays. The pop-only exit for index == -1 (0x37c2675c) PREDATES 1032.
  The defect is the CONTRACT: a callee that may fill nothing, and a caller that assumes it filled.

TWO CANDIDATE FIXES FOR THE NEXT RUNG
  (a) caller-side: after `bl 0x37c266ec`, bound the loop by what was actually written. Cheapest, but
      the callee returns void today, so this needs either a second output or a sentinel.
  (b) callee-side: on every early exit, write a recognisable sentinel (NULL is the honest one) into
      the slot(s) and let the caller's `ldrb [r1,#16]` test for it - the loop already does
      `cmp r1,#0 / beq` right after, so a NULL slot would be skipped if the load were guarded.
  (b) is the smaller edit and matches the caller's existing `cmp r1, #0`.
