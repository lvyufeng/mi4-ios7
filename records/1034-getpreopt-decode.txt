  * THE CONTIGUITY. At the fault (1033 reading) r7 = 0x2bdaa0ac and lr = 0x381959af = the abort
    frame's lr. getPreoptimizedClass's `bl 0x37c26698` at 0x37c2641e sets lr = 0x37c26422 = 0x3819d422
    at slide S, so 0x381959af - 0x3819d422 = lr of that call minus what that call set = -0x7a73, NOT
    zero: the fault's lr is NOT getPreoptimizedClass's return address. Either the pc is not this
    function's walk (P2/P3 in records/1035-carrier-by-pc-read.txt) or some function between them is
    the caller of the walk's frame. NOT SETTLED by this file; the pcc row decides.
  * r4 AT THE FAULT. At 0x37c2645c (the bl to the writer) r4 = sp - 4*r5 and r6 = sp - 8*r5. After
    the call nothing writes r4; the walk's `ldr.w r1,[r6, r0, lsl #2]` at 0x37c2646e reads r6 — which
    the walk NEVER writes. So the frame's r6 = 0x2bdaa088 must be r6 = sp0 - 8*r5 = sp0 + 8 (r5 = -1),
    and sp0 = 0x2bdaa080. The pushes: void w[2] first (r7+4..r7+11 = [sp+0]..[sp+7] relative to the
    post-stmdb sp), then VLA<3> w[r5] at sp = 0x2bdaa080 - 4*0xffffffff = 0x2bdaa084 — the FAULT's r4
    = 0x2bdaa084, VLA<0> = sp0 - 4*r5 = 0x2bdaa084 = 0x2bdaa080 + (uint32)(-1)*... i.e. the value
    the 1032 rule gives for an INDEXED VLA of count (uint32)-1. CONSISTENT: the r4 = sp-4 "contra-
    diction" of E12 resolves IF the walk runs BEFORE the VLA<2>/VLA<3> declarations (C scoping: VLA<2>
    is declared after the walk's block in the source), which the frame's values support.
  * THE LOOP BOUND. `cmp r5,#2; bcc` at 0x37c26448 (unsigned) sends r5 = 0xffffffff INTO the VLA
    path. The walk then reads r6 = sp+8 (r5=-1) and bounds `i < 0xffffffff`.
  * THE ELEMENT READ. 0x37c2646e `ldr.w r1,[r6, i*4]` = the word at sp+8+4i; for i=0 that is
    sp+8 == r7+4 (right ABOVE fp), i.e. the function's own saved {r8,sl,fp}, not the writer's pair
    block. So r6 is NOT the writer's second output (the draft's "pair block" reading is wrong): r1 at
    i=0 = saved r8 = the NAME pointer, and `ldrb r1,[r1,#0x10]` faults only if the name string
    itself is unmapped. In the 1033 frame r1 = 0 and far = 0x10 — read the alternative: the walk ran
    a second time with r1 = 0 in that slot, which the writer (0x37c266ec) must have produced.
  * THE WRITER (0x37c266ec) is a DIFFERENT listing to re-read; bytes raw: section 2. Its own loop
    stores into r4 and r3 (r4 = the first output, r3 = second), so under the walk's r4/r6 = sp-4*r5,
    sp-8*r5 both outputs land in the VLA<0>/VLA<3> frame — the store target of the r1 = 0 word is inside
