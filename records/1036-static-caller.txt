3. SEARCH: WHO CAN PRODUCE count = 0xFFFFFFFF (BYTES + HASH)
====================================================================================================
  (a) The optimised-class table's own words: header [r1+0] and [r1+12] (r1 = the object libobjc is handed
      by dyld in r0 -- the 1035 frame's r8 = 0x38300020 is the *table*, while r1's entry value was 0).
      getPreoptimizedClass guards BOTH against 0 but NOT against -1. If dyld's reader took a field that
      can be -1 (a "class not found" or "no section" sentinel) as a section, count = -1 follows, and the
      VLA arithmetic (r4 = sp+4, r6 = sp+8) reads the function's own saved {r8,sl,fp}. The 1035 frame's
      r1 = 0 (the walk's loaded element) does NOT contradict this: the element read is r6[0] = sp+8.
  (b) A CALLER's return of -1: no CHU16 hit is reachable with count -1 (section 2), so a "not found"
      from the same code family cannot be it unless the call path's lookup shares the miss encoding.
  (c) The stack: r4 = 0x2BD27084, r7 = 0x2BD270AC. The frame therefore lives ~0x20 above the walker's
      sp, on the libobjc caller's stack. Nothing in the published rows reads those slots.
  CHU16 (BYTES of the hash: `h = ror(h,5) + byte`): a reference hash for `_OBJC_CLASS_$_NSObject` is
  0xF01970F2, not a name-table index -- the name table is reached only through 0x37C1E950's compare.
